# oh-my-codex 在本平台中的使用说明

更新时间：2026-04-04

## 1. 先说清楚：它是干什么的

`oh-my-codex` 不是网站前台里的一个按钮插件。

它的作用是：

- 帮你改代码
- 帮你重做页面
- 帮你接接口
- 帮你排查报错
- 帮你做构建检查
- 帮你整理文档

你可以把它理解成：

**一个会直接帮你改“智慧AI教学平台”代码的开发助手。**

## 2. 你现在应该在哪个目录用

本项目的前端目录是：

```bash
/opt/course-platform/nextjs
```

所以你每次要改这个平台，都先执行：

```bash
cd /opt/course-platform/nextjs
```

## 3. 最简单的启动方式

进入项目目录后，执行：

```bash
omx
```

然后你就直接输入中文要求，不需要先学复杂命令。

## 4. 你写提示词的固定模板

以后你要改这个平台，就按这个格式说。

```text
请在当前项目里直接修改代码。

目标：
把【页面/模块】改成【你要的效果】。

要求：
1. 风格是【教育 / 商务 / 科技 / 高端】。
2. 保留【必须保留的内容】。
3. 新增【你要增加的功能】。
4. 不要改动【不能碰的部分】。
5. 改完后自己执行构建检查。
6. 最后告诉我改了哪些文件。
```

你只要会替换方括号里的内容，就能用。

## 5. 你现在最常用的命令

### 5.1 直接开始改

```bash
cd /opt/course-platform/nextjs
omx
```

进去以后直接输入中文。

### 5.2 让它先规划，再动手

```bash
cd /opt/course-platform/nextjs
omx
```

输入：

```text
plan：请先梳理智慧AI教学平台首页改版范围，然后再开始改代码。
```

适合：

- 任务比较大
- 你自己还没想清楚
- 你想先看它理解得对不对

### 5.3 让它持续做完，不要中途停很多次

```bash
cd /opt/course-platform/nextjs
omx
```

输入：

```text
ralph：请直接把首页改版做完，并自己检查构建是否通过。
```

适合：

- 你已经想清楚要什么
- 你希望它直接做
- 你不想它总停下来问

## 6. 可以直接复制使用的提示词

下面这些你可以直接复制。

### 6.1 改首页

```text
请在当前项目里直接修改首页代码。

目标：
把首页改成“智慧AI教学平台”的官网首页，不再只是礼乐课程首页。

要求：
1. 首页必须同时展示礼乐、汽车、水科技、机器人等主题课程占位。
2. 风格要高端、专业、教育商务感强。
3. 页面要有适度动效，但不能花哨。
4. 页面要兼顾 SEO，补齐 title、description、首页可抓取文案。
5. 直接改代码，不要只给方案。
6. 改完后执行构建检查，并告诉我改了哪些文件。
```

### 6.2 改老师端

```text
请直接修改老师端页面。

目标：
把老师端升级成“教师教学与AI备课入口”。

要求：
1. 保留现有课程入口。
2. 增加 AI 生成讲解词、AI 生成课程海报、AI 生成图文内容的入口。
3. 风格与首页统一，不能像后台。
4. 文案要专业，适合老师使用。
5. 改完后执行构建检查。
```

### 6.3 改学生端

```text
请直接修改学生端页面。

目标：
把学生端改成更清晰的路径化学习界面。

要求：
1. 突出主题课程、学习路径、进度状态。
2. 页面风格与首页统一。
3. 不要破坏现有登录和进度展示逻辑。
4. 改完后执行构建检查。
```

### 6.4 改管理端

```text
请直接修改管理端页面。

目标：
把管理端改成平台级管理驾驶舱，而不是普通后台入口页。

要求：
1. 展示平台主题数、课程数、资源数、用户数等概览。
2. 保留内容管理和用户管理入口。
3. 增加 AI 服务状态或 AI 能力入口。
4. 风格统一、专业、商务化。
5. 改完后执行构建检查。
```

### 6.5 接 AI API

```text
请直接在当前项目中接入大厂 AI API。

目标：
在老师端实现“输入主题后，生成课程文案和配图”的能力。

要求：
1. 先检查当前项目环境变量和现有结构。
2. 用统一服务层封装接口调用。
3. 页面上要能实际输入内容并返回结果。
4. 如果缺少 API Key，就把代码接好，并明确告诉我还差哪个环境变量。
5. 改完后执行构建检查。
```

### 6.6 修复 bug

```text
请直接排查并修复当前项目的问题。

问题：
【把你看到的报错贴进来】

要求：
1. 先定位根因。
2. 直接修改代码修复。
3. 不要破坏已有功能。
4. 修完后执行构建检查，并告诉我原因和改动文件。
```

### 6.7 只改文案，不改结构

```text
请直接修改当前页面文案，不改页面结构。

目标：
把文案改成更专业、更像教育商务平台。

要求：
1. 品牌统一为“智慧AI教学平台”。
2. 强调全国中小学、多主题课程、AI教学能力。
3. 文案不要空泛，不要营销过头。
4. 改完后告诉我改了哪些文件。
```

## 7. 你怎么描述需求，效果最好

你说需求时，尽量把下面 5 件事讲出来。

### 7.1 改哪里

例如：

- 首页
- 老师端
- 学生端
- 管理端
- AI 接口
- 登录页

### 7.2 想改成什么感觉

例如：

- 更高端
- 更教育
- 更商务
- 更科技
- 更像 100 万级官网

### 7.3 哪些必须保留

例如：

- 不要破坏登录
- 保留现有课程数据
- 保留老师端入口
- 保留管理端结构

### 7.4 哪些要新增

例如：

- 增加主题课程卡片
- 增加 AI 图文生成入口
- 增加 SEO 文案
- 增加商务合作区块

### 7.5 是否要检查

建议你每次都加一句：

```text
改完后请自己执行构建检查。
```

这样更稳。

如果你暂时不知道怎么组织语言，就直接复制下面这段。

```text

目标：
把这个平台升级为“智慧AI教学平台”。

要求：

6. 改完后执行构建检查，并告诉我改了哪些文件。
```

## 9. 改完后你怎么让它继续

如果第一次改完，你还要继续追加要求，就直接说：

```text
继续，把首页主视觉再做得更高端一点。
```

或者：

```text
继续，把老师端 AI 区域做成真正可提交表单的界面。
```

或者：

```text
继续，把管理端的视觉也统一到首页风格。
```

你不用重新讲一遍全部背景，直接说“继续 + 新要求”就可以。

## 10. 什么时候用 `plan`

当你脑子里只有大方向，没有细节时，用：

```text
plan：请先把这个需求拆解清楚，再开始改。
```

例如：

```text
plan：请先拆解“智慧AI教学平台”首页应该有哪些区块，再开始改代码。
```

## 11. 什么时候用 `ralph`

当你已经明确要它直接做到底时，用：

```text
ralph：请直接完成这个任务并自检。
```

例如：

```text
ralph：请直接完成首页、老师端、学生端、管理端第一期统一改版，并执行构建检查。
```

## 12. 你不建议怎么写

下面这种写法效果通常不好：

```text
帮我改一下，弄高级一点。
```

原因：

- 不知道改哪里
- 不知道什么叫高级
- 不知道是否直接改代码
- 不知道要不要检查

所以最好至少写成：

```text
请直接修改首页代码，把它做成高端教育商务官网风格，保留多主题课程入口，并在改完后执行构建检查。
```

## 13. 如果你想让它只回答，不动代码

你就明确写：

```text
先不要改代码，只告诉我应该怎么改。
```

如果你不写这句，通常会默认直接开始改。
